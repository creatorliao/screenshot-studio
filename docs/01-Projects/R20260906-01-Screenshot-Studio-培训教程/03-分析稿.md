## 1. 作者希望谁、用来干什么？

**一句话结论**：Screenshot Studio 是一个在浏览器里运行、无需注册、无水印的开源「截图编辑器 + 样机制作器」，让用户把一张普通截图/照片，一次做成带背景、样机、3D、标注或动效的可分享成品图或视频。

**证据**：

- `README.md`：*"Free, open-source screenshot editor and mockup maker that runs in the browser. No signup, no watermarks."*；Live 地址 `screenshot-studio.com`，代码出图 `screenshot-studio.com/code`。
- `app/[locale]/page.tsx`（编辑器首页）的 metadata：*"Online screenshot editor and mockup maker that runs in your browser… No signup."*
- `app/[locale]/landing/page.tsx` 的 hero 文案：*"Beautiful images. Zero effort."*、*"Screenshots, ready to ship."*、三步 `howItWorks`：**Drop Your Image → Style It → Export**。

**典型用户 × 典型产出**（仓库有专门受众页可证实）：

| 典型用户 | 仓库依据 | 典型产出 |
|----------|----------|----------|
| 设计师 / UI 设计 | `app/[locale]/for/designers/page.tsx`（*"Mockup & Screenshot Tool for Designers… portfolio screenshots"*） | App/UI 样机、作品集截图 |
| 开发者 | `app/[locale]/for/developers/page.tsx`（*"Beautify code screenshots, terminal output… GitHub readme images"*） | 代码图、README 配图、App Store 截图 |
| 市场营销 | `app/[locale]/for/marketers/page.tsx`（*"product screenshots… landing pages, social media, ads"*） | 落地页图、社媒图、广告创意、推文图 |

**已证实的能力主张**（README Features 与代码核对）：

- 背景：渐变 / mesh / magic / 图片 / 纯色 / 透明，另有「Light & Shadow」阴影贴图。证据：`lib/constants/backgrounds.ts`、`components/editor/sections/BackgroundSection.tsx`、`lib/constants/gradient-colors.ts`、`lib/constants/mesh-gradients.ts`、`lib/r2-backgrounds.ts`。
- 浏览器样机：Safari / Safari Dark / Chrome / Chrome Dark。证据：`components/editor/sections/BrowserMockupSection.tsx`。
- 设备样机：iPhone 17 Pro、iPhone 17、iPhone 15、iPhone 13、iPhone 14 Pro、Apple Watch（7 款）、MacBook Pro / Neo / Air 15 / Pro 14 / Pro 16。证据：`lib/constants/mockups.ts`。
- 3D 透视与阴影、标注、代码出图、推文出图、动画时间轴、导出 PNG/JPEG/WebP、视频 MP4/WebM。证据见下文 §3。

## 2. 心智模型是什么？

**冻结的 7 格模型**（后续所有课用这套名字，不得改）：

```
① 获得画面 → ② 定画幅 → ③ 套样机与画框 → ④ 调背景与深度 → ⑤ 标注与文字 → ⑥ 加动效(支线) → ⑦ 导出
```

每一格对上的界面分区 / 代码模块：

| 格 | 用户动作 | 界面入口 | 代码证据 |
|----|----------|----------|----------|
| ① 获得画面 | 上传 / 粘贴 / 输入网址截图 / 导入推文 | 空态上传区、Design 面板的 Tweet 导入 | `components/controls/CleanUploadState.tsx`、`components/editor/sections/TweetImportSection.tsx`、`app/api/screenshot/route.ts` |
| ② 定画幅 | 选比例 / 尺寸 | Header 的 Aspect Ratio 选择器 | `components/editor/EditorHeader.tsx`、`lib/constants/aspect-ratios.ts` |
| ③ 套样机与画框 | 选浏览器 / 设备 / 样式 | 左栏 Mode 切换（Image/Browser/Device） | `components/editor/LeftEditPanel.tsx`、`BrowserMockupSection.tsx`、`DeviceFramesSection.tsx`、`StyleSection.tsx` |
| ④ 调背景与深度 | 换背景、加阴影、叠贴纸/物体、图层管理 | 左栏 BG 与 Layers 标签 | `BackgroundSection.tsx`、`DepthSection.tsx`、`ImageOverlaySection.tsx` |
| ⑤ 标注与文字 | 画箭头/形状/模糊、加文字 | Design 面板 Draw & Markup、Add Text | `AnnotateSection.tsx`、`TextSection.tsx`、`components/text-overlay/` |
| ⑥ 加动效（支线） | 选动画预设、拖时间轴 | 右栏 Motion、画布下方 Animate、时间轴 | `components/editor/RightSettingsPanel.tsx`、`components/timeline/`、`lib/animation/presets.ts` |
| ⑦ 导出 | 选格式/质量/倍率，下载或复制 | Header 的 Save / Copy / Export Video | `components/canvas/dialogs/ExportDialog.tsx`、`components/export/`、`lib/export/` |

**说明**：作者在落地页自己的三步（Drop → Style → Export）与本模型的 ①→(②③④⑤)→⑦ 一致；②③④⑤ 是「Style」的展开，⑥ 是支线。

## 4. 主路径与支线分别是什么？

**主路径**（一步一张卡片）：

| # | 用户动作 | 看到什么 | 模型节点 |
|---|----------|----------|----------|
| 1 | 打开编辑器，拖入/粘贴一张图，或输入网址截网页 | 图片进入画布，左右两侧面板出现 | ① |
| 2 | 顶部选画幅（比例） | 画布比例变化 | ② |
| 3 | （可选）套浏览器/设备样机，或选样式 | 图片被框/玻璃/描边包住 | ③ |
| 4 | 换背景、加阴影、叠贴纸 | 画面整体氛围变化 | ④ |
| 5 | 画箭头/加文字 | 标注出现在图上 | ⑤ |
| 6 | 点 Save，选格式/质量/倍率，导出 | 浏览器下载一张图 | ⑦ |

**支线清单**（每条写清「从主路径哪一步分出」）：

| 支线 | 从主路径哪步分出 | 回到哪步 | 对应课 |
|------|------------------|----------|--------|
| 代码出图 | 独立页 `/code`，不经过主路径 | 导出 PNG 后回到使用场景 | 04 |
| 推文导入 | ① 获得画面（不传图，改用推文链接） | 导入后进入 ② 继续主路径 | 04 |
| 动画 + 视频导出 | ⑦ 之前（③④ 之后加动效），或 Add Slide 多图 | 导出视频后结束 | 04 |
| 公开截图 API | `/docs`（`app/[locale]/docs/page.tsx`、`app/api/screenshot/route.ts`） | 与编辑器主路径无关 | 不进 01~06 正文，附录一句带过 |

**默认判定（取证后确认）**：主路径 = 上传或网页截图 → 编辑器美化 → 导出静态图；`/code`、推文导入、动画/视频导出是支线；API 是产品另一能力，不是本系列主路径。与方案 §4.4 默认判定一致。

## 5. 作为一个用户，第一次应该怎么走？

| 路径 | 适用 | 步骤来源 | 第一次成功长什么样 |
|------|------|----------|--------------------|
| 线上 | 只想先用起来 | `README.md` Live 地址 | 打开 `screenshot-studio.com`，看到空态上传区，能放入一张图 |
| 本地 | 要对照源码学 | `README.md`、`CONTRIBUTING.md` | `npm install` 后 `npm run dev`，打开 `localhost:3000`，进入同一编辑器 |

**核心功能不需要环境变量**：证据 `README.md`（*"Core features need no environment variables"*）、`CONTRIBUTING.md`（*"Core features work with no configuration"*）。R2 资产存储、Postgres 截图缓存、分析均为可选。

**环境变量文件**：README/CONTRIBUTING 提到 `.env.example`，但**本仓库未提交该文件**（`.gitignore` 第 34 行 `.env*` 忽略，`git ls-files` 无 `.env.example`）。排障附录按「未提交、可自行按 CONTRIBUTING 说明配置」处理，不虚构文件内容。

**本地要求**：Node.js 20+ 与 npm（`CONTRIBUTING.md`）。`package.json` 的 `dev` 脚本会先 `npx prisma generate` 再 `next dev --webpack`；即使没有 `DATABASE_URL`，首次 `dev` 也可能因 Prisma 生成需要数据库 URL 而报错——此点写进排障附录，作为「可选配置可能绊住第一次启动」的真实失败点。

## 6. 作者希望用户怎样决策？（工作方法）

这些是从信息架构和默认工作流反推的，每条有证据：

1. **先想「给谁看、用在哪」，再动手**。画幅选择器按用途分门别类（Instagram / Social Media / YouTube / Pinterest / App Store），说明作者默认用户按「去处」先选尺寸。证据：`lib/constants/aspect-ratios.ts` 的 `category` 与 `useCase` 字段。
2. **先把画面放进画布，再美化**。空态只有「上传 / 粘贴 / 截网页」一个入口，功能面板在放入图片后才出现。证据：`components/controls/CleanUploadState.tsx`、`components/editor/EditorLayout.tsx`（`hasSourceContent` 才显示 Animate/时间轴）。
3. **默认先套样机或样式，再调背景**。左栏 Design 标签在 Image 模式下先给 Style/Border/Shadow，BG 是独立标签。证据：`LeftEditPanel.tsx`。
4. **背景是「氛围」，样机是「容器」**。背景面板同时提供纯图、渐变、magic 渐变和阴影贴图，且背景可单独调模糊/噪点，说明作者把「背景与深度」当成一层可独立调的东西。证据：`BackgroundSection.tsx`、`SettingsSection.tsx`。
5. **最后才决定导出格式与倍率**。导出弹窗的顺序固定为 Format → Quality → Resolution → Export，倍率默认 2x。证据：`components/canvas/dialogs/ExportDialog.tsx`、`components/export/ScaleSlider.tsx`、`hooks/useExport.ts`（`DEFAULT_SETTINGS`）。
6. **可逆、可复用**。有撤销/重做、Reset to defaults、自动草稿、导出偏好记忆，作者默认用户会反复试。证据：`EditorHeader.tsx`、`hooks/useAutosaveDraft.ts`、`lib/export-storage.ts`。
