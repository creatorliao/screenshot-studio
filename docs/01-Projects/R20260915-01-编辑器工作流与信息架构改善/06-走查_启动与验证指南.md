## 2. 启动

### 2.1 生产模式（**走查推荐用这个**）

```powershell
npm run build     # 约 2–4 分钟
npm start         # 起在 http://localhost:3000
```

推荐理由：dev 模式首次访问每个路由都要现场编译（`/` 要 51 秒，见 §2.4），
手工走查时会把"白屏等待"误判成"页面坏了"。

### 2.2 开发模式

```powershell
npm run dev       # 起在 http://localhost:3000
```

### 2.3 怎么算"启动成功"

看到这三行就算成功：

```
▲ Next.js 16.1.6 (webpack)
- Local:        http://localhost:3000
✓ Ready in 5.2s
```

然后确认首页返回 200：

```powershell
(Invoke-WebRequest http://localhost:3000 -UseBasicParsing).StatusCode   # 期望 200
```

**实测记录**：`npm run dev` → `Ready in 5.2s`；`npm run build` → exit 0，全部路由生成。

### 2.4 两种"看起来像启动失败"的正常现象 —— 别误报

| 现象 | 真相 | 怎么办 |
|---|---|---|
| **dev 模式首次打开 `/` 白屏约 50 秒** | Next.js dev 按需编译，实测 `GET / 200 in 53s (compile: 51s)`。**生产模式无此问题** | 等它；后续路由 7–25 秒。走查请用 §2.1 生产模式 |
| 终端出现 `⚠ The "middleware" file convention is deprecated. Please use "proxy" instead.` | Next.js 16 的弃用提醒，**不影响功能** | 忽略。要消除得改 `middleware.ts` 文件名，属独立工作 |
| 控制台 1 条外部 404 + PostHog token 报错 | 既有配置问题（`cdn.palmframe.com` widget-config、PostHog 未配 token），**非本次改动引入** | 见 §5 |

> **`npx prisma generate` 每次都会先跑**（`dev` / `build` 脚本里带着），
> 输出 `✔ Generated Prisma Client` 是正常的，不是报错。

## 3. 自动化验证链（5 道门，按顺序跑）

### 门 1 · 类型

```powershell
npx tsc --noEmit -p tsconfig.json
```

- **通过标准**：exit code `0`，**且没有任何输出**。
- 实测：`tsc exit=0`。
- 若报错集中在 `i18n-work/`：那是汉化备份目录，`tsconfig.json` 的 `exclude` 已排除它；
  若又冒出来说明有人动了 `exclude`。

### 门 2 · 静态检查

```powershell
npm run lint
```

- **通过标准**：`0 error`，exit code `0`。
- 实测（合并上游 `main` 之后）：`✖ 106 problems (0 errors, 106 warnings)`，**exit 0**。
  106 条 warning 全部是既有的（`no-explicit-any`、`no-console`、`exhaustive-deps`），不阻断。
- 注意：`eslint` 配置**忽略了 `scripts/` 目录**，所以 `scripts/user-sim.mjs` 不参与 lint
  （单独 lint 会提示 `File ignored because of a matching ignore pattern`）。这是配置现状，不是错误。

> **历史沿革（避免下次误判）**
>
> 合并上游之前，这道门**不是全绿的**：`npm run lint` 以 `exit 1` 报 4 条 error ——
> `ArcFrameOverlay.tsx:67,68`（`prefer-const`）、`useCachedImage.ts:35`
> （`react-hooks/rules-of-hooks`：hook 在 `forEach` 里调用，调用次数会随数组长度变化）、
> `useExport.ts:339`（三元表达式当语句）。**这 4 条与编辑器改造无关，是改前就在的。**
> 合并上游 `main` 时上游恰好改了这三个文件，**4 条 error 一并消失**，这道门现在是干净的。
>
> 另：`eslint.config.mjs` 的 `ignores` 原本没有 `i18n-work/**`，汉化流水线的备份树
> 被当源码 lint，**同一批问题数了两遍（error 从 4 条虚增到 10 条）**。
> 已补上 `i18n-work/**` 与 `.sim/**`。

## 4. 手工走查（核心）

自动化能挡住"功能坏了"，挡不住"用起来别扭"。这一节验的是后者。

### 4.0 走查前必做：清空本地状态

**不做这一步，你会看到和第一次进来不一样的结果**（有三处状态存在 `localStorage`）：

| 键 | 影响 |
|---|---|
| `screenshotstudio-post-import-hint-dismissed` | 「下一步」指引只显示一次 |
| 背景面板的最近使用 / 收藏 / 上次分类 | 会带着上一轮的数据 |
| 导出格式偏好 | 会记住你上次选的 PNG |

**做法**：开一个**无痕窗口**，或 DevTools → Application → Storage → **Clear site data**。

> 想验"第一次进来的人看到什么"，就必须用干净状态。

### 4.1 首屏（空画布）—— 用户投诉的第一条

打开 `http://localhost:3000`。

| 操作 | 预期看到 | 不通过说明什么 |
|---|---|---|
| 直接看首屏 | 大标题 **「把图片放进来」** | 还是"一个加号 + 一行小字 + 一个 URL 框"→ 首屏引导没生效 |
| 看主入口 | **三个带文字的**并列按钮：`选择文件` / `网页截图` / `粘贴或拖放` | 缺任意一个 → 入口没收全 |
| 看说明文字 | `导入后可以调整画幅、背景和文字，最后导出成 PNG / JPEG / WebP` + `支持 PNG / JPG / WebP，单个最大 100MB` | 缺 → 用户不知道能传什么、传多大 |
| 看头部 | Logo 右侧有一个**常驻**按钮，文字是 **「导入」** | 没有 → 常驻入口没生效 |
| 看左栏 | **不应出现**「设计 / 背景 / 图层」Tab | 出现了 → 空画布还在渲染无效控件 |
| 看右栏 | **不应出现** 3D 预设、阴影那一堆 | 同上 |
| 按 F12 看 Console | 无红字（§5 列的三条除外） | 有红字 → 记下来，见 §7 |

### 4.7 换主图（保留样式）—— 本次最高优先级修复

| 直接 Ctrl+V 粘贴一张图 | 与拖放同一条路径 |

> **这是本次修的核心问题**：改造前用户**没有任何一条**"换主图但保留样式"的路径，
> 五种尝试全部走不通。

## 5. 控制台里什么算问题、什么不算

**这一节是为了防止你把既有噪声当成"本次改坏了"。**

### 5.1 预期会出现（**不是缺陷**，实测稳定复现 3 条）

| 消息 | 来源 | 性质 |
|---|---|---|
