## 3. 需求拆解（把原话翻译成可验收的条目）

### R1 · 首屏导入必须"一眼就知道怎么开始"

- **现状痛点**（用户原话）：进入界面后不知道怎么上传要处理的"文档"。
- **需求**：用户进入编辑器、画布还空着的时候，必须能**不假思索**地看到"从哪里把图片放进来"，
  并且知道这个动作会产生什么结果。
- **要求**：
  - R1.1 导入入口必须**有文字**说明（不能只有图标）。
  - R1.2 导入方式要覆盖普通用户的主流习惯：点击选择文件、拖拽、粘贴、按网址抓取。
  - R1.3 首屏要说明**支持的格式与大小上限**，以及失败时会怎样。
  - R1.4 导入完成后，界面要给出"下一步做什么"的指向（而不是把用户丢到一堆面板里）。

### R2 · 采用引导式导入（Import Wizard / 引导式导入）

- **需求**：从"空画布"到"图片已经摆在画布里"之间，插一段**有步骤感的引导**，
  明确回答：① 图从哪来 ② 要什么画幅/用途 ③ 要不要套样机。
- **约束**：引导不能变成每次都要走的强制流程；老用户必须能一步跳过。
- **待确认**：见 §6 Q1（引导 vs 非引导的取舍）。

### R3 · 按"核心工作流"重排功能，而不是按"功能分类"堆面板

- **需求**：把现有功能按下面这条主线归位，并让每一步的用户都能看到"我走到哪了"：

  ```
  ① 导入图片  →  ② 调整图片（画幅/位置/大小/圆角/边框/阴影/滤镜）  →  ③ 设置背景
  →  ④ 添加文字与标注  →  ⑤ 导出（多种格式）
  ```

- **要求**：同一条主线上的一步，只能有一个明确入口；不允许同一个动作在多个面板各有一份。

### R4 · 背景设置要"好用"，不只是"能用"

- **现状痛点**（用户原话）：改背景的那些按钮用起来不方便，功能存在但不方便。
- **需求**：
  - R4.1 换背景要**少点几下**、**看得清**、**选得准**。
  - R4.2 当前背景必须**随时可见可回退**（现在选中了什么、上一步是什么）。
  - R4.3 背景候选要**可分类、可搜索/筛选、可预览**，不能只靠在一排 32px 小色块里肉眼找。
  - R4.4 常用的几款要能"记住/最近使用/收藏"。

### R5 · 文本与其他叠加元素要有统一的"加—选—改"路径

- **需求**：用户说"设置其他的文本框"，说明"文本框"是核心工作流的一步。
  - R5.1 新增文本的入口要显眼、位置固定、有文字标签。
  - R5.2 新增后要**自动进入编辑态**（光标已经在文字里），而不是让用户再找一次输入框。
  - R5.3 文本、贴纸、标注、模糊区块要能用**同一套图层概念**管理（选中、层级、显示/隐藏、删除）。

### R6 · 导出要覆盖"各种格式"，并且找得到

- **需求**：导出（图片多格式 / 视频 / 批量 / 复制到剪贴板）必须**位置固定、条件可预期**，
  不能"有时出现有时不出现"让用户找不到。
- **要求**：
  - R6.1 导出入口常驻可见（图片不满足条件时置灰，而不是消失）。
  - R6.2 格式、质量、倍率要有**面向用途**的解释（发微信 / 进 PPT / 留底稿）。
  - R6.3 导出前的尺寸与体积预估要给出来。

### R7 · "当前的排版能力感觉怪怪的"——需要定位到具体是什么怪

- **待查**：用户主观感受，需要调查取证后落到具体条目（面板宽度、Tab 只有图标、分组全展开、
  同义多入口、控件层级混乱、间距与分组不一致等）。
- **要求**：不能把"怪"笼统处理，必须逐条给出证据 + 改法。

### R8 · 符合大多数人的使用习惯，不为好看而乱搞

- **需求**：改动的判据是"主流同类工具（Shots.so / Pika / CleanShot / Canva / Figma）的用户习惯"，
  不是视觉炫技。
- **要求**：任何改动都要能回答"这解决了哪一条用户动作的低效"，答不出来就不改。

## 7. 判定标准（做成什么样算做成）

1. 一个没看过教程的中文用户，进入编辑器后 **30 秒内**能自己完成"导入一张图 → 换一次背景 → 导出一次"。
2. 上面 J1–J7 每一步的**操作步数**比现状减少，或步数不变但**可见性/可预期性**显著提升（有证据说明）。
3. 同一个动作在界面上**只有一个主入口**（允许"高级入口"作为副路径，但必须是主入口的从属）。
4. 首次进入不会被"看起来能点但其实无效"的控件误导（空画布时无效控件必须隐藏或禁用并说明）。
5. 用户能回答"我现在在哪一步、下一步要干什么"。
