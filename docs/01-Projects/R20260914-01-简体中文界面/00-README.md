## 一句话结论

**简体中文译文是齐的（`messages/zh.json` 与英文 135/135 键对齐），语言路由也是通的
（实测 `Accept-Language: zh-CN` → `307 /zh`），唯独 UI 渲染层从未接线
（全仓 0 处 `useTranslations`，约 750 处英文硬编码）。**

因此 `/zh` 页面的**可见 DOM 中文字符数为 0**——中文只存在于 RSC 序列化脚本里，没有任何组件读它。
当前**不存在任何让用户看到中文界面的办法**，换 URL、切浏览器语言都不行。

这是"半接线"的国际化：路由层做完了，渲染层没做。

## 关键提醒

1. **改 `defaultLocale` 是错误的第一反应**。它既不能让你看到中文（文案仍是英文硬编码），
   又会把线上英文根路径 `/` 的 SEO 权重搬到 `/en/*`。真正的必改项是渲染层接线。
2. **36 处 `next/link` 必须一并换成语言感知的 `Link`**，否则从 `/zh` 点任意导航都会掉回英文，
   前面的成果在用户第一次点击时全部失效。
3. **不需要重写中文译文**，只需扩充新键（现有 `editor` 段仅 12 键，实际需要数百键）。
