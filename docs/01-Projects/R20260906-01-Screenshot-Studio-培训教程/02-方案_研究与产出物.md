> 文档性质：执行方案（给写课智能体使用）  
> 落盘位置：`docs/01-Projects/R20260906-01-Screenshot-Studio-培训教程/`

> 用法：先完整阅读需求，再按本方案取证、交分析稿、按文件清单写系列课。本方案规定「交什么、从哪取证、写成哪几个文件」；学习目标与验收仍以需求为准。  
> 本方案不代替教程正文。未取证前，不把下面的功能名当成已证实结论。

## 1. 方案要解决什么

需求已经写死学习结果：理解 → 学会 → 应用。智能体缺的是一份**交稿合同**：

- 研究先回答哪几个问题、证据从仓库哪几处取  
- 最终落盘哪些文件、每个文件写什么、彼此如何引用  
- 先交哪一份、后写哪一课，避免没模型就开写操作步骤  

一句话：**需求管「学习者最后必须能做到什么」；本方案管「执行者按什么顺序、交出哪些稿件」。**

---

## 2. 工作原则（写任何一课前先守住）

1. **先分析稿，后教程。** 没有心智模型和证据索引，不准写 00 以后的操作课。  
2. **证据优先于文笔。** 每条功能、按钮名、格式、数量必须能指回文件或路由。对不上就标「未证实」，不进正文。  
3. **README 与代码冲突时，以代码和实际界面为准**，并在分析稿写明差异。  
4. **教程按工作流读，源码按附录查。** 禁止把 `components/` 目录树当成目录。  
5. **练习不空。** 01～06 必须有自检；02～06 必须有迁移练习；06 必须换素材或换用途。  
6. **不改产品代码。** 只写文档、只建 PARA 与分支。

## 4. 研究设计：七问怎么答

分析稿必须按下面七节组织，节名不要换。每一节结尾用「证据」列表标路径。写课智能体只消费「已证实」行。

### 4.1 作者希望谁、用来干什么？

**要产出的结论形态：** 一段话 + 一张「典型用户 × 典型产出」表。

**取证顺序：**

1. `README.md` 的定位与 Features  
2. `app/[locale]/landing/page.tsx`、`app/[locale]/about/page.tsx`  
3. 受众页：`app/[locale]/for/designers/page.tsx`、`for/developers/page.tsx`、`for/marketers/page.tsx`  
4. 功能页：`app/[locale]/features/page.tsx` 及 `screenshot-beautifier`、`browser-mockups`、`code-snippets`、`social-media-graphics`、`animation-maker`、`3d-effects`  
5. 编辑器默认入口 `app/[locale]/page.tsx`、代码出图 `app/[locale]/code/page.tsx`

**禁止：** 用竞品对比页的营销句当事实，除非能在编辑器或导出实现里复核。

### 4.2 心智模型是什么？

**要产出的结论形态：** 一张不超过 7 格的模型（可用 mermaid 或编号列表），外加「每一格对应的界面分区 / 代码模块」。

**建议先用这条骨架去核对，核完再改名字，不要先发明另一套：**

```
获得画面 → 放入画布 → 套样机/画框 → 调背景与深度 → 标注与文字 → 定画幅 → 按规格导出
```

**取证：** `components/editor/` 分区、`components/canvas/`、`components/export/`、`lib/store/`、`CONTRIBUTING.md` 的 Project Structure。每一格至少挂一个界面入口和一个文件路径。挂不上的格删掉或降为支线，不要硬留。

### 4.3 有哪些功能？挂在模型哪一格？

**要产出的结论形态：** 功能表，列必须包含：

| 用户能感知的能力 | 模型节点 | 界面入口（分区/路由） | 证据路径 | 主路径或支线 | 状态（已证实/未证实） |
|------------------|----------|----------------------|----------|--------------|----------------------|

**起步时优先核对这些入口（以实际代码为准，名称以界面文案为准）：**

- 取画面：`UploadArea.tsx`、`WebsiteScreenshotInput`、`TweetImportSection.tsx`、`app/api/screenshot/route.ts`  
- 样机 / 设备：`BrowserMockupSection.tsx`、`DeviceFramesSection.tsx`、`components/canvas/frames/`  
- 背景 / 深度 / 阴影 / 边框：`BackgroundSection.tsx`、`DepthSection.tsx`、`ShadowSection.tsx`、`BorderSection.tsx`、`lib/constants/backgrounds.ts`  
- 标注 / 文字 / 叠加：`AnnotateSection.tsx`、`TextSection.tsx`、`ImageOverlaySection.tsx`  
- 变换 / 位置：`TransformsSection.tsx`、`PositionSection.tsx`、`ImagePositionSection.tsx`  
- 代码出图：`app/[locale]/code/page.tsx`、`components/code-image/`  
- 动画：`components/timeline/`、`lib/animation/`  
- 导出：`components/export/`、`lib/export/`、`lib/workers/export.worker.ts`  
- 草稿 / 预设：`DraftIndicator.tsx`、`components/presets/`

数量级（背景数、主题数、导出倍率等）必须数自常量或 UI，禁止照抄 README 而不复核。

### 4.4 主路径与支线分别是什么？

**要产出的结论形态：**

- 主路径：一步一张卡片（用户动作 → 看到什么 → 进入模型哪一格）  
- 支线清单：每条写「从主路径哪一步分出、回到哪一步、对应哪一课」

**默认判定（取证后可改，但要在分析稿写理由）：**

- 主路径 = 上传或网页截图 → 编辑器美化 → 导出静态图  
- 支线候选 = `/code` 代码出图、推文导入、动画时间轴导出、公开 API（`app/[locale]/docs/page.tsx`）  
- API 文档默认**不进入 01～06 正文**，最多在附录提一句「产品另有截图 API，不是本系列主路径」

### 4.5 第一次应该怎么走？

**要产出的结论形态：** 两条启动路径 +「第一次成功」的定义。

| 路径 | 适用 | 步骤来源 | 第一次成功长什么样 |
|------|------|----------|--------------------|
| 线上 | 只想先用起来 | README 的 Live 地址 | 打开编辑器，能放入一张图 |
| 本地 | 要对照源码学 | `README.md`、`CONTRIBUTING.md`、环境变量示例 | `npm run dev` 后打开本地编辑器 |

写明：核心功能不需要环境变量；R2 / 数据库 / 分析标成可选。环境变量文件以仓库里实际存在的示例名为准（若无 `.env.example`，写 CONTRIBUTING 里的说明，不要虚构文件）。

### 4.6 作者希望用户怎样决策？

**要产出的结论形态：** 5～7 条工作方法，每条能从信息架构或默认工作流反推。

建议核对顺序（仍须证据）：先定用途与去处 → 选画幅 → 放入画面 → 选样机 → 调背景 → 必要时标注 → 最后选导出格式与倍率。

界面上「默认先打开哪一块、导出弹窗里先选什么」是方法的证据；不要把培训者自己的设计口味写成作者方法。

### 4.7 证据索引

**要产出的结论形态：** 两张表。

1. **已证实索引**：模型节点 → 界面入口 → 关键路径（可直接剪进 `附录-代码对照表.md`）  
2. **未证实清单**：原计划要写、但仓库找不到的能力；教程正文禁止出现

## 6. 单课交稿规格

除 `03-分析稿.md`、`00-README.md`、`00-学习地图.md`、两份附录外，每一课按需求 §8 的六段写，标题建议固定，便于验收扫描：

```markdown
# 0N · 课名

## 本课目标
## 它在模型的哪一格
## 跟做步骤
## 自检
## 迁移练习
## 证据
```

补充约定：

| 段落 | 硬性规格 |
|------|----------|
| 本课目标 | 2～3 句；点明理解 / 学会 / 应用中的哪一层 |
| 它在模型的哪一格 | 必须引用 `00-学习地图.md` 里的同一套节点名，禁止另起别名 |
| 跟做步骤 | 编号；命令整段可复制；用产品真实用词；每 3～8 步给一次「你应该看到什么」 |
| 自检 | 3～5 条可打勾的句子，用「我已经…」 |
| 迁移练习 | 写清：任务、可用条件、怎样算做成；与跟做示例在素材或用途上必须不同 |
| 证据 | 文件或路由列表；没有证据的步骤删掉 |

`00-学习地图.md` 用精简骨架即可：作者意图、心智模型图、主路径与支线、各课对照表。可以没有迁移练习，但必须有「不看界面，复述模型」的自检。

`06-综合应用.md` 的任务不得复用 02 课的同一张示例图、同一个用途。题面至少包含：给谁看、用在哪、素材从哪来、必须用到的模型节点、怎样算做成。做成后要学习者用模型里的词写五句以内复盘。

`附录-代码对照表.md` 从分析稿 4.7 剪出，只保留已证实行。不要在附录里新写操作步骤。

## 7. 推荐的迁移练习与综合题（写课时填写具体素材，此处只定约束）

这些是**题型**，不是题面。智能体取证后把「仓库里真能做的事」填进去，不要提前锁死素材 URL。

| 课 | 跟做（由作者带着） | 迁移（学习者自己做） |
|----|--------------------|----------------------|
| 01 | 按文档启动到看见编辑器 | 换一种方式再进一次（线上 ↔ 本地，能做则做） |
| 02 | 一张现成截图走完导出 | 换自己的一张图，仍走同一条最短路径 |
| 03 | 在主路径各节点各改一处 | 指定用途（例如「放进文档的产品图」），自选样机与背景 |
| 04 | 一条已证实支线走通 | 说明它从主路径哪一步分出；第二条支线可标选做 |
| 05 | 导出一种格式与一种倍率 | 按「发推 / 放进幻灯 / 留底稿」选不同规格（以产品实有选项为准） |
| 06 | 无跟做，只有题 | 综合：新素材 + 新用途 + 至少覆盖取画面、一样机或背景、一处标注或文字、一次导出 |

若某条支线取证后不存在，04 课相应练习删除，并在分析稿未证实清单留痕，禁止用假步骤补齐。
