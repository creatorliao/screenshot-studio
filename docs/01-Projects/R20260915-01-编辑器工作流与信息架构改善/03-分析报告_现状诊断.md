## 1. 结论先行（一段话）

**这个工具的功能不是不够，而是"没有为任何一条用户旅程编排过"。**
15 条导入入口、318 个背景候选、14 处死代码 UI、3 套"有没有图"的判据、5 个（桌面）/6 个（移动）互不一致的 Tab，
全部平铺在同一个 260px 侧栏 + 一个 340px 弹窗里。用户面对的不是"功能少"，而是**"每一步都要先做一次考古"**。

具体到用户提出的两件事：

1. **"不知道怎么上传"** —— 首屏确实有一个居中的虚线加号区，文案是「拖放、点击浏览或粘贴」。
   但它被**左右两个塞满控件的面板夹在中间**（左 9 个区块、右 34 个 3D 预设），且这些控件在没图时**照样可点、但什么都不会发生**。
   更关键的是：**头部没有任何"导入"按钮**，一旦画布有了图，唯一的导入入口（中央那块）就永久消失，
   而「添加幻灯片」只在已有幻灯片时出现 → **用户拿不到一个稳定的"我要导入"入口**。

2. **"改背景的按钮不方便"** —— 不是按钮画得不好，是**它把 318 个候选塞进 212px 宽的纵向长条里**：
   渐变色块 32px、无名字、无 hover 预览、无搜索、无收藏、滚动条被 CSS 隐藏、
   11 个分组每次进来都全展开、从"光与影"滚到"渐变"要滚约 3 屏、两个横向画廊分别有 4.7 屏和 10.7 屏的内容。
   **这不是"不方便"，这是"让你在 318 个无名色块里靠肉眼找一针"。**

**一句话病根**：**功能按"实现分类"堆叠，没有按"用户动作顺序"编排。**

## 3. 七类根因（按对用户的伤害排序）

### R1 · 没有"导入"这个一等公民（伤 J1）

- 头部 12 个控件里，**没有一个叫"导入/上传/打开"**。
- 唯一的导入 UI 绑在"空画布"状态上（`EditorCanvas.tsx:135-136`），有图即消失。
- 空画布时左右面板**照常全量渲染**（`LeftEditPanel.tsx:138-150`、`RightSettingsPanel.tsx:591-603`），无任何禁用或遮罩。
  → 用户进入后看到的是"一个已经开好的编辑器和一堆控件"，而不是"请先放一张图"。
- 佐证：产品内**只有推文导入**给了流程引导（「获取、预览、再添加到画布」），说明团队知道该怎么做，只是没推广到主路径。

### R2 · 最基础的"换一张图"这条路径是断的（伤 J1）

这是本次调查最严重的单项发现：

| 用户动作 | 实际结果 |
|---------|---------|
| 把新图**拖到已有作品的画布上** | **变成一张贴纸叠加层**（`GlobalDropZone.tsx:56-71`），主图不变 |
| 用中央区域重新上传 | 中央区域**已经不存在了** |
| 用头部「添加幻灯片」 | 只在已有幻灯片时出现，且会把主图切回第 1 张（`lib/store/index.ts:1484`） |
| 点「移除」再上传 | 会执行 `clearImage`，**特效、背景、文字、贴纸全部清空** |
| 用空画布 URL 抓图 | `setImage()` **重置全部特效与背景**（`lib/store/index.ts:802-888`） |

→ **用户没有一条"换主图但保留我的样式"的路径。** 这是工作流的第一环，却最破。

### R3 · 背景面板是"按素材分类"而不是"按选择效率"设计的（伤 J4）

- 11 组、318 个目标、全部 `defaultOpen`。
- 渐变类候选 32px、**无 alt/title/aria-label**、无 hover 预览、无名字、无搜索、无收藏。
- 横向画廊内容宽 992px / 2272px，可视 212px，而 `scrollbar-hide` 把滚动条彻底隐藏。
- 选中态用两套视觉语言（图片=加边框，渐变=变圆放大），**都没有对勾或文字**。
- 补充伤害：阴影不在 BG 面板里完成（要跳去图层 Tab 调）；背景的模糊/颗粒也不在 BG 面板里（在"设计"→"颜色滤镜"里）。

### R4 · 工作流被切碎在 5/6 个 Tab 里，且桌面与移动不一致（伤 J3–J6）

- 桌面：左 3 Tab（设计/BG/图层）+ 右 2 Tab（3D/动效），中间隔着画布。
- 移动：一个面板 6 Tab（设计/图层/BG/调整/3D/动效）。
- **两套结构不一致** → 桌面独缺「位置九宫格」「独立调整 Tab」；同一个"调整"在移动端是独立 Tab、在桌面端是"设计"Tab 的最底部。
- Tab 名混杂：`设计 / BG / 图层` 与 `3D / 动效`——同一层级里中英混排、缩写与全称混排。
- 结果：用户要建立两套（甚至跨端的）心理地图，且**无法预测某个功能在哪个 Tab**。

### R5 · 同一个动作有多个入口、多个状态口径（伤 J3，也让 bug 难以定位）

- 缩放：2 个入口且乘法叠加；位置：3 套实现（1 套可达、2 套死）；边框：2 套 UI 写同一字段。
- "有没有图"：3 套判据不等价 → 加载失败时头部与画布判断分裂且**无任何错误提示**。
- 导入后的重置语义：`addImages` 不重置 / `setImage` 全重置 → **同样是"第一次导入"，走拖拽和走 URL 抓图结果完全不同**。
- 校验规则：全局只校验第 1 张、`/tools` 允许 GIF/BMP/AVIF 而编辑器不允许、有 3 处完全不校验。

### R6 · 幽灵入口与失效导航（让用户怀疑自己）

- **14 处**已实现、已导出、但界面上到不了的编辑器 UI（另一套左栏、右栏、导出弹窗、上传区、画布工具条、叠加层管理、草稿指示器…）。
- **一处确证失效的导航**：左栏「贴纸」里的「N layers / 管理深度与素材」按钮在桌面端**点了没有任何反应**（写 store，但桌面右栏不认 `'depth'`，左栏又不读 store）。
- 后果：用户形成"这个按钮好像有、好像没用"的经验，进而**不再相信界面**。

### R7 · 编辑器里塞营销与状态噪声（伤整体的"专业感"）

- 头部上方有 `CodeImagesBanner` 营销横幅（「New — Code Images…Try it」），编辑器正文上方还有 `MobileBanner`。
- **自动草稿是静默的**：`useAutosaveDraft()` 有 `isSaving/lastSaved` 返回值，但 `EditorLayout.tsx:42` 直接丢弃；`DraftIndicator.tsx` 是死代码。
  → 用户重新打开工具会**莫名看到上次的作品**，且不知道"这是恢复的草稿"还是"软件出错了"。
- 界面中英混杂（`BG`、`3D`、7 个背景分类名 Abstract/macOS/Radiant/Mesh/Raycast/Paper/Pattern、`SHUFFLE` 未译）。

## 5. ⚠️ 阻断性发现：工作树正在被并发改写（改造前必须先冻结基线）

- 调查期间（06:11–06:23）**另一个会话正在同一工作树里跑一套 i18n 流水线**：

### 5.3 为什么这件事仍然是"阻断性"的（别因为只剩 1 处就放松）

1. **行号是不可靠的**：本主题所有行号以 06:20–06:26 的工作树为基准，流水线**再跑一次就全部失效**。
2. **文案改造必然与它冲突**：IA 重排要动 JSX 里的文案位置，而 `i18n-apply.ts` 是按字符串匹配的，**两者同时进行必然互相覆盖**。
3. **同类风险尚未审计完**：本次只确认了 7 处；**其余 160+ 个改动文件中是否还有"值级误译"未知**
   （例如 `lib/constants/mockups.ts`、`lib/aspect-ratio-utils.ts` 等数据表里大量 `name` 字段被翻译，
   是否有别处按英文 `name` 做匹配，本轮未逐个核对）。这类问题 `tsc` **抓不到**。
4. **一个 4 分钟改两次代码的工作树，不适合作为任何改造的起点**。

### 5.4 行动建议（P0，必须最先做）

1. **先请启动这条流水线的会话/人停下来**，确认 `i18n-apply` 不会再跑。
2. 把当前工作树**提交到一个独立分支并冻结**（例如 `feat/i18n-zh`），作为唯一基线。
3. 在 `tsconfig.json` 的 `exclude` 里加上 `i18n-work` —— 否则 44 条备份噪声会继续淹没真实错误。
4. 修掉残留的 `TransformsGallery.tsx` 那一处；并用"**在数据表里按 `name` 值做匹配**"为线索做一次人工巡检。
5. 决定文案策略（继续硬编码中文 / 接 next-intl）。**若接 next-intl，本主题的 IA 重排应直接写 key，一次到位。**

### 5.5 与 `R20260914-01-简体中文界面` 的关系

- 「界面恒为英文」的根因（渲染层从未接线）由该主题负责，其结论仍然成立（`useTranslations` 命中 0）。
- 但该主题的**施工方式**（脚本批量替换硬编码字符串）就是上面这条风险的来源。
- **顺序建议**：汉化流水线停下并冻结 → 修残留回归 → **然后再开本主题的 IA 重排**。两者串行，不要并行。

## 6. 需求与现状对照（回答"我们要求的核心工作流，代码里在哪"）

| 用户要的核心工作流 | 代码里存在吗 | 是否成为"主路径" | 差距 |

**结论：五步全都有实现，没有一步是"缺功能"。缺的是"把五步串成一条线"。**

## 7. 改造优先级建议（依据 = 用户伤害 × 修复成本）

| 优先级 | 事项 | 为什么排这个位置 |
|--------|------|------------------|
| **P0** | 请流水线停下 + 冻结 i18n 基线 + 修残留回归（当前 1 处） | 不冻结，后面所有改动都建在会自己移动的地基上 |
| **P0** | 首屏引导式导入 + 常驻「导入」入口 | 用户明确投诉的第一条；工作流第一环 |
| **P0** | 修好"换主图"路径（拖入=替换而非变贴纸；换图保留样式） | 最严重的工作流断裂；成本低（改判定分支 + 加确认） |
| **P1** | 背景面板重构（分类 Tab + 大预览 + 搜索 + 最近/收藏 + 命名） | 用户明确投诉的第二条；伤害最大 |
| **P1** | 桌面/移动统一为一套 Tab；补回"位置"控件 | IA 的骨架，决定后面所有面板怎么放 |
| **P1** | 空画布时禁用/隐藏无效控件 | 成本极低，消除"点了没反应" |
| **P2** | 图层系统补全（重命名/锁定/排序）+ 文字提到显眼位置 | 提升效率，非阻断 |
| **P2** | 导出面板常驻入口 + 用途化文案 + 尺寸/体积预估 | 收尾体验 |
| **P2** | 清理 14 处死代码 UI；修失效导航 | 降低维护成本与用户困惑 |
| **P3** | 草稿状态可见化（恢复提示 / 保存指示） | 消除"莫名恢复上次作品"的疑惑 |

- [ ] 同一动作只有一个主入口。→ 现状缩放 2 个、位置 3 个、边框 2 套、导入 15 条。**不通过**。
- [ ] 空画布时不会被无效控件误导。→ 现状左右面板全量渲染且不禁用。**不通过**。
