# 需求：Screenshot Studio 简体中文界面

- 项目夹：`docs/01-Projects/R20260914-01-简体中文界面/`
- 提出人：廖海（liaohai1）· 简体中文用户
- 记录日：2026-09-14
- 对象仓库：`D:\code\screenshot-studio`（分支 `dev-creator`）
- 状态：**已记录，方案待确认，尚未施工**

## 1. 原话

> 这个项目当前启动的时候总是英文界面的。我是一个简体中文的用户，你看一下它的默认启动参数是不是有问题，
> 还是它根本就没有预留简体中文的文本？希望你帮我调查研究一下。
> 我希望下一次进去的时候，应该是简体中文文本的界面。不要马上执行。

## 2. 需求陈述

一句话：

> 本地启动 Screenshot Studio 后，界面（可见文案）应当以**简体中文**呈现，而不是英文。

拆成可验收的三条：

| # | 需求 | 说明 |
|---|------|------|
| R1 | **可见文案中文化** | 页面正文、按钮、菜单、工具栏、表单标签、占位符、报错提示等所有用户可见文本为简体中文 |
| R2 | **默认进入即中文** | 本地启动后打开根路径，无需手动改 URL、无需每次重新设置，直接就是中文界面 |
| R3 | **语言选择可切换且可记忆** | 提供语言切换入口；选择一次后下次访问仍保持简体中文 |

## 3. 用户提出的两个待判定问题

用户最初给出两种假设，本次调查需要给出明确判定（详见 `02-调查_英文界面根因取证.md`）：

| 假设 | 判定 | 依据摘要 |
|------|------|----------|
| H1：默认启动参数有问题 | **部分成立，但不是主因** | `npm run dev` 无任何语言参数；语言协商实测生效（`/` + `Accept-Language: zh-CN` → `307 /zh`）。参数层面没有把语言钉死在英文 |
| H2：根本没有预留简体中文文本 | **不成立** | `messages/zh.json` 存在且与 `en.json` **135/135 键完全对齐**，是完整可用的简中译文 |
| H3（调查中新发现）：预留了文本但 UI 层完全没接 | **成立，这才是主因** | 全仓 **0 个**组件/页面调用 `useTranslations` / `getTranslations`；约 **750 处**英文硬编码；`/zh` 页面可见 DOM 中文字符数为 **0** |

## 4. 验收标准

做完之后，用下面的检查项判定"真的成了"：

1. 清空浏览器 Cookie 后访问 `http://localhost:3000/`，界面文案为简体中文。
2. 在任意页面能看到语言切换入口，且能切到"简体中文"。
3. 切换后跳转其它页面（如 `/about`、`/tools`），语言**不丢**，仍是中文。
4. 关闭浏览器重开，仍为中文（选择被记住）。
5. 浏览器控制台无 next-intl 缺失 key 的 warning；`Missing message` / `MISSING_MESSAGE` 不出现。
6. `<html lang="zh-CN">`（或 `zh`）与界面语言一致。
7. 页面 `<title>`、meta description、OG 标签与界面语言一致（否则分享出去仍是英文）。

## 5. 范围

**做：**

- 界面可见文案接入 next-intl 翻译体系
- 语言切换入口 + 选择持久化
- 默认语言与语言协商的最终行为固化
- 页面 metadata（title/description/OG）随语言变化
- 导航链接带上语言前缀，跨页不丢语言

**本轮不做（可另开需求）：**

- 除简体中文以外的 6 个语种（es/fr/de/ja/pt/ko）的文案补全与校对
- 中文排版细节优化（标点挤压、字重、中西文混排间距）
- SEO 层面多语种 hreflang / 多语言 sitemap 的完整方案
- 把 `/zh` 从 `noindex` 放开（涉及 SEO 策略决策，需单独确认）
