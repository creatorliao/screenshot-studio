### 2.3 P0-4 修「换主图」路径（治 R2 —— 本次最高优先级功能修复）

改造前用户**没有任何一条**"换主图但保留我的样式"的路径（`03-分析报告` §3 R2 的五种尝试全部走不通）。现在：

- 新增 store 动作 `replaceMainImage(file, { resetStyles })`：只换主图，不动背景/阴影/圆角/缩放/滤镜/文字/贴纸/标注/动效。
  - 同时把该图所在的幻灯片 `src` 一起换掉，并在**确认没有别的幻灯片还引用旧 URL** 之后才 `revokeObjectURL`（改造前 `setImage` 直接回收，会连带打断仍指向它的缩略图）。
- 拖放/粘贴落在已有主图上 → 默认**替换主图（保留样式）**；按住 **Shift** 才是"添加为贴纸"。
  - 拖拽浮层实时改文案：标题「松开即导入」/「松开即添加为贴纸」，副标题「将替换主图，已调好的背景与文字会保留」，小字「按住 Shift 松开 = 添加为贴纸」—— 结果不再静默。
- 多文件时首张换主图、其余转为贴纸，**不再静默丢弃**。

### 2.4 P0-4 空画布不再渲染无效控件（治 R1）

- 新增 `hooks/use-has-renderable-content.ts`：把改造前**三套不等价**的"有没有图"判据收成一处
  （`EditorCanvas` 要两个 store 都认、`EditorHeader` 只看 `screenshot.src`、`ClientCanvas` 又是第三种）。
  取**最严**口径（两个 store 都认），因为 `screenshot.src` 才是 `ClientCanvas` 真正渲染的字段。
  → 主图加载失败时头部与画布不再判断分裂。
- `EditorLayout`：空画布时**收起** `LeftEditPanel`、`RightSettingsPanel` 与移动端「设置」入口。
- 实测效果：`/` 页面可见中文字符由 **948 → 464** —— 少掉的正是那堆"点了没反应"的控件文案。

**开发模式下首次访问 `/` 的编译耗时 51 秒**（`GET / 200 in 53s (compile: 51s)`）——
冷启动第一次打开会长时间白屏，很容易被判断成"跑不起来"。这是 Next.js dev 的预期行为
（后续页面 7–25s，生产模式无此问题），**不是缺陷**，但值得知道。

另外确认了两条与启动无关、但会在控制台刷红的**既有**噪声（非本次改动引入，见 §6.4）。

### 6.3 模拟中发现并修掉的 2 个真实缺陷

这两个都不是类型检查能发现的，只有"真的去点"才暴露：

| # | 缺陷 | 症状 | 修法 |
|---|---|---|---|
| 1 | `BackgroundSection` 的背景上传 dropzone `accept` 是**非法组合**：`{ 'image/*': ['jpeg','jpg','png','webp'] }`（通配 MIME + 扩展名） | react-dropzone 打印 `Skipped "image/*" because an invalid file extension was provided.` 并**把该条整条丢弃** → `accept` 形同虚设，任何类型都会进 `onDrop`，只剩 `validateFile` 兜底 | 按 MIME 正确声明 `image/png` / `image/jpeg` / `image/webp` |
| 2 | 重构背景面板时，候选卡片按钮**漏写 `relative`**（改造前的旧代码是有的） | `CachedImage` 内部用 `next/image` 的 `fill`，需要已定位父元素 → 控制台刷 7 条 `has "fill" and parent element with invalid "position"`，且**选中对勾的 `absolute inset-0` 会锚到错误祖先** | 候选按钮与阴影按钮都补回 `relative`，并把这条提升为模拟脚本的断言 |

> 缺陷 2 是本次**自己引入**的回归 —— 说明"重构一个 318 候选的面板"这件事，
> 光靠 `tsc` + 肉眼比对 diff 不够，必须有运行期断言兜住。

### 6.4 模拟过程中出现过的三次"假警报"（诚实记录，避免误读）

调试过程中脚本自己报过 3 次失败，**全部是测试写法问题，不是应用缺陷**：

1. `nextjs-portal` 被判成"错误浮层" —— 其实它是 Next.js dev-tools 的挂载点，
   任何 dev 页面都有。改为检查 shadowRoot 里是否真有 `[data-nextjs-dialog]`。
2. "阴影候选 22 个（应为 19）" —— 多出的 3 个来自**始终挂载但隐藏的「模板」覆盖层**
   （`LeftEditPanel` 里 `PresetGallery` 只靠 `-translate-x-full opacity-0` 隐藏），
   它的预设预览图引用了 `041/017/019` 三张阴影图。改为只在特效面板的网格内计数。
3. "点击渐变没生效" —— `button[title]` 的 `.first()` 先命中了**编辑器模式开关**
   （它同样有 `title` 与 `aria-pressed`，`title="图片"`），于是"点渐变"实际点的是"切到图片模式"。
   改为把选择器收窄到背景面板作用域。**这一条尤其值得记**：如果当时不去读
   `#canvas-background` 的计算样式，就会误判成"背景切换功能坏了"。
