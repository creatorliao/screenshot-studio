## 0. 先说结论（30 秒版）

把这个工具从**"功能面板集"**改造成**"五步流水线"**：

```
① 导入图片  →  ② 调整图片  →  ③ 设置背景  →  ④ 加文字与标注  →  ⑤ 导出
```

**核心思想**：主路径只保留一条、每步只有一个主入口，高级能力（3D 透视、动画时间轴、设备样机、推文/代码导入）降级为"从属入口"。
**不做**：不做视觉炫技、不重做配色/动效、不追求"看起来高级"。

## 1. 设计原则（全部来自用户原话，作为后续所有取舍的裁判）

| # | 原则 | 裁判作用（举例） |
|---|------|------------------|
| P1 | **按用户动作顺序排列功能，不按功能分类排列** | 背景的模糊/颗粒要从"设计"Tab 移到"背景"步骤里 |
| P2 | **同一步骤只能有一个主入口** | 缩放的两个入口删掉一个；位置的 3 套实现收敛成 1 套 |
| P3 | **看得见才算存在**：入口要有文字、候选要有名字、当前状态要有明确标识 | 渐变色块要有名称 + 对勾；头部要有常驻「导入」 |
| P4 | **不为好看而乱搞**：任何改动都要能回答"它解决了哪条用户动作的低效" | 不加装饰性动效、不加没用的渐变 |
| P5 | **符合大多数人的使用习惯**：对标 Shots.so / CleanShot / Canva 的既有心智 | 左侧步骤条 + 右侧属性面板；中央画布；导出用弹窗而不是 340px Popover |
| P6 | **引导式导入，但绝不强制**：可一键跳过，老用户第二次进来不该看到 | 向导只在"空画布 + 首次访问"出现 |

**产品内已有的正面样板**：头部的画幅选择器（`aspect-ratio-picker.tsx`）——按平台分组、每个选项带用途说明、420px 够宽。
**改造风格应统一向它看齐。**

## 2. 目标信息架构（推荐形态）

### 2.1 空画布（首次进入 / 无作品）

```
┌──────────────────────── 顶部：导入 / 模板 / 我的草稿 …（导入为第一顺位，常驻）───────────────────────┐
│                                                                                                  │
│                    ┌──────────────────────────────────────────┐                                  │
│                    │            把图片放进来                    │                                  │
│                    │  ┌────────┐ ┌────────┐ ┌────────┐        │                                  │
│                    │  │ 选择文件│ │ 网页截图│ │ 粘贴/拖放│       │                                  │
│                    │  └────────┘ └────────┘ └────────┘        │                                  │
│                    │  支持 PNG / JPG / WebP，单个最大 100MB      │                                  │
│                    │  （可选）帮我选个画幅 →                      │                                  │
│                    └──────────────────────────────────────────┘                                  │
│                                                                                                  │
│  ← 左右侧栏在空画布时**收起或整体禁用 + 遮罩**，不出现任何无效控件                                     │
└──────────────────────────────────────────────────────────────────────────────────────────────────┘
```

**与现状的差别**：新增常驻「导入」入口；把"选画幅"作为导入的同屏可选项；**空画布时左右栏不再全量渲染**。

### 2.2 有作品（正常工作态）

```
┌── 顶部：导入(替换) · 模板 · 撤销/重做 · 画幅 · 复制 · 保存▾ · 导出视频 · 移除 ────────────────────────┐
├──────────────┬────────────────────────────────────────────────┬──────────────────────────────────┤
│  步骤条       │                                                │   当前步骤的属性面板               │
│  (左侧 72px   │                  画布（中央）                    │   （右侧 300px，只显示当前步骤的）   │
│   图标+文字)  │                                                │                                  │
│              │                                                │   例：步骤③ 背景 →                │
│  ① 图片  ●   │                                                │   · 分类 Tab（纯色/渐变/图片/…）    │
│  ② 调整       │                                                │   · 大预览网格（≥64px + 名称）      │
│  ③ 背景  ←   │                                                │   · 搜索框 + 最近/收藏             │
│  ④ 文字标注   │                                                │   · 背景模糊/颗粒（从"设计"搬来）   │
│  ⑤ 导出       │                                                │                                  │
│              │                                                │                                  │
│  ─────────   │                                                │                                  │
│  ⚙ 高级       │                                                │                                  │
│   · 3D 透视   │                                                │                                  │
│   · 动效/时间轴│                                               │                                  │
│   · 设备样机  │                                                │                                  │
│   · 推文/代码 │                                                │                                  │
└──────────────┴────────────────────────────────────────────────┴──────────────────────────────────┘
```

**关键点**：
- 左侧从"设计/BG/图层 三个 Tab + 模式三选一"变成**一条步骤条 + 一个高级抽屉**。
- 右侧只显示**当前步骤**的属性 —— 这样"设置背景"时不会看到 3D 滑杆。
- 「图片 / 浏览器 / 设备」模式（现有 `editorMode`）收进**步骤②的一个选择项**，而不是放在最上方当全局开关。
- 中央画布始终居中、面积最大化（现在被 260+260 挤掉 520px）。

| 维度 | **方案 A · 小改（低风险）** | **方案 B · 中改（推荐）** | **方案 C · 大改** |

## 4. 方案 B 详细设计（7 个模块）

### 模块 1 · 引导式导入（治 J1，对应 `01-需求` R1/R2）

**改什么**

1. **头部新增常驻「导入」按钮**（放在最左，Logo 右侧），永远可见：
   - 空画布：文案「导入图片」，点击打开导入面板。
   - 有作品：文案「替换图片」，点击后**替换主图但保留样式**（见模块 2），并提供「追加为贴纸」次要选项。
2. **重写空画布中央区**（改造 `CleanUploadState`，不是新建）：
   - 标题从「拖放、点击浏览或粘贴」改为**动宾结构的大标题**：「把图片放进来」。
   - 三个并列的**带文字**入口：`选择文件` / `网页截图` / `粘贴或拖放`（现状是"一个加号 + 一行小字 + 一个 URL 框"混在一起）。
   - 补上现状完全缺失的信息：**支持 PNG / JPG / WebP，单个最大 100MB**（数据来自 `lib/constants.ts:6-7`，直接展示，不要写死）。
   - 加一句**下一步指引**：「导入后可以调整画幅、背景和文字」。
   - 保留快捷键提示，但把未译的 `to paste` 修掉。
3. **空画布时收起/禁用左右侧栏**：这是本次改动里"性价比最高"的一条 —— 用户进来不会再看到一堆点了没反应的控件。
4. **可选：导入后引导**（不做强制向导）：导入完成后在右侧属性面板顶部给一行提示「① 图片已导入 → 下一步：调整 / 背景 / 文字」，三点可直接跳步骤。

**为什么不做强制向导**：老用户每次进来都过一遍向导是负体验；用"空画布中央区 + 导入后提示"就能达到引导效果，且随时可跳过。

**怎么验证**：让一个没用过的人打开页面，只看 3 秒，问他"你会点哪里把图放进来"。

---

### 模块 2 · 修好"换主图"（治 R2，本方案的最高优先级功能修复）

**改什么**

1. `GlobalDropZone` 的判定分支（`GlobalDropZone.tsx:53-80`）：
   - 现状：`isEditorPage && hasMainImage` → 一律作为**贴纸叠加层**。
   - 改为：弹出一个轻量选择（或按修饰键区分）——默认「**替换主图**」，次要「添加为贴纸」。
   - 兜底：如果用户直接拖入且不选择，默认替换主图（符合大多数人的直觉）。
2. **替换主图必须保留样式**：现状 `setImage()` 会重置背景/阴影/圆角/缩放/动画（`lib/store/index.ts:802-888`）。
   新增一个"只换图"的路径：仅更新 `uploadedImageUrl` / `screenshot.src` / 可选 `imageName`，其余字段不动。
   同时提供「同时重置样式」的勾选项（默认不勾）。
3. 让三条导入路径的语义一致：拖拽 / 点击浏览 / 粘贴 → **"首次导入"与"替换主图"行为一致**；URL 抓图不再静默重置。

**为什么**：这是用户工作流的第一环，也是目前唯一一条"完全走不通"的路径。

**怎么验证**：做一次"换图"操作，确认背景、文字、贴纸都还在。

---

### 模块 3 · 背景面板重构（治 J4/R3，对应用户投诉第二条）

**改什么**

1. **分类 Tab 化**：把现在纵向堆叠的 11 个分组，改为横向分类 Tab：
   `纯色 | 渐变 | 图片 | 特效`（或保留细分为 `渐变 / 魔法渐变 / 图片·Abstract / 图片·macOS / …`，但必须一次只显示一类）。
2. **候选放大并命名**：
   - 图片缩略图从 `grid-cols-4` 小图改成**至少 64px 的大预览**（`grid-cols-2`/`3` + 名称）。
   - 渐变/魔法渐变色块从 32px 提到 **≥56px**，**必须带名称**（现在连 `title` 都没有）。
   - 选中态统一为「对勾 + 描边 + 名称加粗」，不再用"变圆+放大"这种第二套语言。
3. **加搜索框**：至少支持按名称搜渐变/图片分类；这是 318 个候选的必要配套。
4. **加"最近使用"与"收藏"**：复用现有 `localStorage` 偏好写法（`hooks/useCustomPresets.ts` 已有类似设施），不做后端。
5. **加 hover 预览**（可选但推荐）：hover 时在画布上临时应用，离开还原 —— 这是"选得准"的关键。
6. **把背景相关的调整搬进来**：`背景模糊` 与 `颗粒` 从「设计→颜色滤镜」（`SettingsSection.tsx:93-126`）移到背景步骤；补上**背景不透明度**（现在完全无 UI）。
7. **阴影（光与影）重新归位**：它现在其实是"图层"，要么移到"图层/装饰"步骤，要么在背景面板里做成"阴影"分组但**允许直接调不透明度**（现在硬编码 0.5，要跳去图层 Tab）。
8. **修复三格高亮的错误**：用预设图/渐变时"自定义背景"三格不该全灭。
9. **修复"删除自定义背景"语义**：应恢复上传前状态，而不是强行设成某个橙色渐变。
10. **让折叠/分类选择被记住**（现状切 Tab 即重置为全展开）。

**为什么**：这一条直接对应用户原话"那些按钮使用得并不方便。功能是存在的，但是就是不方便"。

**怎么验证**：从"渐变"换到"某张图片背景"，操作 ≤3 次，且中途能说出"我现在在哪个分类、当前选的是哪个"。

### 模块 4 · 统一为一套步骤化布局（治 R4/R7，`01-需求` R3）

**改什么**

1. `EditorLayout` 从「左栏 260 + 画布 + 右栏 260」改为「**左侧步骤条 72px + 画布 + 右侧属性面板 300px**」。
2. 步骤：`① 图片 ② 调整 ③ 背景 ④ 文字标注 ⑤ 导出`，末尾一个「⚙ 高级」抽屉放 3D / 动效 / 设备样机 / 推文 / 代码。
3. **删除桌面/移动两套 IA**：`UnifiedRightPanel` 与 `LeftEditPanel` 收敛成一套组件、两种呈现（宽屏=步骤条+属性面板；窄屏=抽屉）。
4. **找回桌面端丢失的能力**：`ImagePositionSection`（位置九宫格）必须回到步骤②；`SettingsSection` 的滤镜/画布进入步骤②；`TransformsGallery` 进入「高级 → 3D」。
5. `editorMode`（图片/浏览器/设备）从"最上方的全局开关"降级为**步骤②里的一个选择项**。
6. 补一步**空画布时的步骤态**：五个步骤全置灰 + 步骤①高亮，箭头明确指向"从这里开始"。

**为什么**：这是"功能要按核心工作流排列"的落地方式；也是唯一能同时消除"桌面缺控件""Tab 名中英混杂""功能不可预测"的办法。

**成本提示**：这是本方案唯一一次真正的布局重构，也是风险集中点。建议在 P1 阶段单独排期。

### 模块 6 · 导出（治 J7，`01-需求` R6）

**改什么**

1. **入口常驻**：把「保存」改为常驻的「导出」，条件不满足时**置灰并说明原因**，而不是让「导出视频」整个消失。
2. **从 340px Popover 改为 480–560px 弹窗**（对齐画幅选择器的 420px 逻辑），一次看全：格式 / 质量 / 倍率 / 预估尺寸 / 预估体积。
3. **文案面向用途**：
   - PNG =「无损，支持透明，适合留底稿」
   - JPEG =「体积小，适合发微信/网页」
   - WebP =「体积最小且清晰，适合现代网页」

4. **补 GIF 入口**：GIF 编码代码已存在（`lib/export/ffmpeg-encoder.ts`），只是没接 UI；要么接上，要么把 `llms.txt` 等处的 GIF 承诺删掉，**不要留矛盾**。
5. **导出后给"最近导出"入口**（可选）：现在导出后无任何记录（`lib/export-storage.ts` 明确不再写 IndexedDB）。

## 6. 依赖、风险与回滚

### 6.1 与汉化主题的依赖（重要）

- **必须先决定文案策略**：继续"硬编码中文"还是"接 next-intl"。
  - 若接 next-intl：IA 重排时**直接把文案写成 key**，一次到位（推荐）。
  - 若继续硬编码：本次重排会把大量文案从 A 文件搬到 B 文件，**`i18n-apply.ts` 的字符串匹配会失效或错配**，必须在本主题结束后再重跑。
- **不要并行施工**。建议顺序：汉化回归修复 → 冻结基线 → 本主题 IA 重排。

### 6.2 主要风险

| 风险 | 说明 | 缓解 |
|------|------|------|
| R-1 布局重构引入回归 | 模块 4 动 `EditorLayout`，影响所有面板挂载 | 先冻结基线；一个 PR 只做布局，不夹带其他改动；保留旧布局开关便于对照 |
| R-2 状态收口引入 bug | "有没有图"判据收敛、`setImage`/`addImages` 语义统一会触及 store | 单独一步做，配单测（`tests/` 已有 `tsx --test` 设施） |
| R-3 文案搬迁与 i18n 脚本冲突 | 见 6.1 | 串行施工 |
| R-4 高级能力被"藏起来"引发老用户不满 | 3D/动效/设备降级到「高级」 | 「高级」抽屉保持一级可见；提供"记住上次打开的步骤" |
| R-5 反复改动导致用户学习成本 | 一次性改完比零敲碎打好 | 按 P0→P1→P2 分批但每批都对外可见、有 changelog |

### 6.3 回滚

- 所有改动走独立分支（建议 `feat/editor-ia`），基于冻结后的 `feat/i18n-zh`。
- 模块 4（布局）单独 commit，必要时可单独 revert。
- 死代码"归档"而非删除，降低误删风险。

## 8. 施工纪律（写给未来的执行者，含我自己）

1. **先看 `03-分析报告` §5** —— 基线没冻结就不要动任何文件。
2. **一次只动一个模块**，每个模块一个 commit，commit message 写清"解决 `02-调查` 里的哪条证据"。
3. **不为了好看而改**：新增任何视觉元素前，先写出它解决的低效动作；写不出来就不加。
4. **改完必须回填 `02-调查` 的行号**（i18n 已让行号漂移过一轮）。
5. **每个阶段结束用 J1–J7 记录前后步数**，作为"有没有真的变好用"的证据，而不是靠感觉。
